# NL-1: natural-language geometry--forgetting external validation

**Protocol date:** 2026-08-24  
**Study status:** design frozen; **not launch-ready**  
**Blocking conditions:** split-aware data preparation, a timing/memory-only GPU
profile, and an explicit compute budget  
**Scientific role:** second (real-web) layer of the required language program;
never a replacement for Path-Star, HMM, or CFS-2  
**Declaration provenance:** the original frozen FineWeb-Edu declaration is retained
unchanged; the prospective language-program amendment adds TS-1 without rewriting
that declaration

## Question and claim boundary

NL-1 is an **exploratory external-validity study** and asks:

> In web-derived English, does a retention prefix's pre-update hidden-state
> proximity to a disjoint continued-pretraining stream predict how much its fixed
> natural continuation deteriorates after that update, and is this association
> stronger for NextLat than for an architecture-matched GPT?

This is deliberately narrower than the controlled experiments. Natural text does
not expose an exact Bayesian belief state or an oracle partition of histories into
predictively equivalent classes. NL-1 therefore tests a **representation--forgetting
association**, not exact predictive-state recovery and not a causal mediation claim.
Only the update itself is causal; hidden-state proximity is observed, not randomly
assigned.

NL-1 cannot rescue a null, failed, or confounded core result. It will be reported in
a separate section after the controlled results, regardless of direction. A positive
NL-1 result with a null core is hypothesis-generating external evidence only; a null
NL-1 result does not invalidate a clean task-specific core result.

NL-1 now forms the second layer of a two-study language program. The first layer,
**TS-1**, is a focused GPT/NextLat-d=1 TinyStories parity and positive-control arm
using the authors' synthetic-language dataset, 100,000-step base schedule, and
20-offset probe family. NL-1 remains the new real-web geometry--forgetting arm. Both
must complete for the project to claim the full language external-validity program;
neither is permitted to alter the controlled-study conclusions.

## Dataset decision

The study uses **FineWeb-Edu `sample-100BT`, pinned to dataset revision `v1.0.0`**,
with a GPT-2 tokenizer. FineWeb-Edu is filtered real-world web text derived from
Common Crawl. It is not a certified human-authored corpus: web pages can contain
machine-generated material, residual duplication can survive dataset processing,
and FineWeb-Edu's educational-quality filter was trained using Llama-3 annotations.
We will describe it as **filtered real-world web text with an LLM-assisted quality
filter and residual contamination risk**, not simply “human ground truth.”

The revision is pinned because the official NextLat pretokenizer does not specify a
dataset revision and the live FineWeb-Edu repository has changed since its initial
release. NL-1 is consequently a reproducible extension at the pinned NextLat code
commit, not a claim of byte-identical reconstruction of the authors' unpinned
FineWeb-Edu stream.

Sources:

- [FineWeb paper](https://arxiv.org/abs/2406.17557)
- [FineWeb-Edu dataset card](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu)
- [TinyStories paper](https://arxiv.org/abs/2305.07759)
- [NextLat v4](https://arxiv.org/abs/2511.05963)

### Why both TinyStories and FineWeb-Edu, but not Manhattan?

- **TinyStories is now TS-1, the parity layer.** Its 2.7 million stories were
  generated by GPT-3.5 and GPT-4. The pinned NextLat experiment trains 8-layer,
  768-dimensional models for 100,000 steps on 256-token sequences and then trains
  20 future-token probes. Reusing that setup directly addresses implementation
  parity with v4, while its synthetic provenance prevents it from serving as the
  only external-validity evidence.
- **Manhattan is not language.** It consists of random traversals grounded in a real
  Manhattan street graph (91 million sequences and 4.7 billion tokens in the
  paper), not prose or dialogue. It offers a known structured world model, but the
  official 48-layer models train for 400,000 steps/six epochs, approximately 26.2
  billion token exposures. It tests structured state tracking, not natural-language
  external validity.
- **FineWeb-Edu is the required real-web layer.** The main NextLat paper
  trains 1.3B-parameter models on 100B tokens; NL-1 instead adopts the repository's
  official 100M-class GPT and NextLat configurations and a preregistered 2B-token
  budget. This is exploratory triangulation at roughly 1/13 the parameter scale and
  1/50 the token exposure of v4, not a replication or matched-scale challenge to the
  paper's 1.3B/100B language-modeling evidence.

## Outcome-blind corpus construction

The current upstream pretokenizer concatenates streamed documents into token shards
and does not preserve a manifest that proves document-level separation. That is
insufficient for this study. Before any training, a new data-preparation step must:

1. stream `HuggingFaceFW/fineweb-edu`, config `sample-100BT`, revision `v1.0.0`;
2. use the stable source `id` when present, otherwise SHA-256 of the exact UTF-8 text,
   as `document_id`;
3. reject duplicate document IDs globally;
4. compute `bucket = SHA256("nl1-v1|split|" + document_id) mod 23`, assigning
   buckets 0--19 to base, 20 to retention, 21 to episode 0, and 22 to episode 1;
   traverse the pinned stream once and accept whole documents into their assigned
   split until each minimum token quota is filled:

   | Split | unique GPT-2-token quota | purpose |
   | --- | ---: | --- |
   | base | 2,000,000,000 | base pretraining only |
   | retention | 100,000,000 | validation and fixed retention spans only |
   | adaptation episode 0 | 100,000,000 | CE-only update branch |
   | adaptation episode 1 | 100,000,000 | independent CE-only update branch |

5. add one EOS token per document, never allow a retained prefix/continuation span
   to cross EOS, and preserve document-boundary masks required by NextLat losses;
6. record dataset revision, tokenizer revision/files, document IDs, source URLs when
   available, per-split counts, token counts, and SHA-256 for every emitted shard;
7. run an exact duplicate check and a preregistered token 5-gram MinHash audit across
   splits. Exact duplicates block launch. Near duplicates are reported; the frozen
   rule removes both members when estimated Jaccard is at least 0.80, then fills the
   deficit by continuing the same pinned stream and bucket rule.

No loss, checkpoint, activation, generated completion, or scientific metric may be
read during data construction. The corpus is not selected by a language model's
performance.

### Frozen retention and update anchors

From the retention split, choose the first 2,000 eligible documents in ascending
`SHA256("nl1-v1|retention|" + document_id)` order. Each contributes exactly one span:

- 512 GPT-2 tokens of prefix;
- the immediately following 128 tokens as the fixed scored continuation;
- start offset selected by
  `SHA256("nl1-v1|offset|" + document_id) mod (n_tokens - 640 + 1)`.

Documents shorter than 640 tokens are ineligible; they are skipped without looking
at model values. One span per document makes the document, not the token, the
retention observation.

For each adaptation episode, select 4,096 eligible anchor documents in the analogous
hash order and extract one 512-token prefix per document. Anchors are used only to
summarize the pre-update geometry of that episode's already-frozen training stream;
they do not select or weight adaptation examples.

## Models and training

Use the pinned NextLat repository commit
`3770be6009cea2b3c455a9ce7f2ca88b504bb955` and derive configurations from:

- `config/fineweb/100M/gpt_finewebedu.yaml`, SHA-256
  `0570c8bc7a3a7bebe9608741e018e45678da8581aba75bcbd8b09f9f91a3b851`;
- `config/fineweb/100M/nextlat_finewebedu.yaml`, SHA-256
  `ed0a56c90a21b998a5e427d3929c9be2508f1f8ef2eeaf1e9ad9012e0ec3c0d0`.

The paired models have 12 layers, 12 heads, hidden width 768, context length 1,024,
GPT-2 vocabulary, and the same next-token head. The NextLat arm uses the official
100M-class settings: one-step latent prediction, Smooth-L1 weight 1.0, KL weight
1.0, and projection factor 1.3. BST is not added: the pinned repository provides no
100M FineWeb BST configuration, and importing the 1.3B BST setup would change both
scale and compute by a large factor.

Run paired seeds `3234`, `3235`, and `3236`. Three pairs are a budget-conscious
external-validation sample and are not sufficient for a high-resolution seed-level
exact test; inference emphasizes paired estimates and uncertainty rather than a
binary significance claim.

### Frozen budget-scale deviations

NL-1 intentionally changes the official 10B-token 100M-class schedule to a
2B-token schedule:

- `train_batches = 3814`, giving 1,999,634,432 token exposures at effective batch
  512 and block size 1,024;
- `lr_scheduler.schedule = wsd` explicitly (the 100M YAML writes warmup/warmdown
  values but otherwise inherits `constant`, which would ignore them in the pinned
  trainer);
- 200 warmup updates;
- 400 warmdown updates;
- one final checkpoint at update 3814; durable recovery checkpoints every 500
  updates and on termination, with exact optimizer/RNG resume only.

This scale was chosen before model outcomes to make three paired seeds plausible on
the available hardware while retaining approximately 20 tokens per 100M-class model
parameter. It must not be expanded or reduced after inspecting an NL-1 metric. A
different token budget creates NL-2.

On a single 24GB GPU, the effective batch remains 512. A timing/memory-only profile
may increase gradient accumulation and reduce physical microbatch size until the
configuration fits. This is an execution equivalence, not a scientific tuning
parameter; the chosen accumulation, precision, compilation status, and measured
throughput are frozen in a pre-run receipt.

## Continued-pretraining intervention

Fork each final base checkpoint into the two fixed episode branches. Restore the
exact model weights, then initialize the same fresh adaptation optimizer for both
models: AdamW, learning rate `1e-4`, weight decay `0.1`, betas `(0.9, 0.95)`, gradient
clip `1.0`, and constant schedule. Reinitializing avoids inheriting a near-zero final
base learning rate or model-specific Muon state. Branch RNG/data order is the same
fixed hash function of seed and episode for both models. Then perform **100
full-parameter CE-only updates** on that episode's disjoint stream:

- GPT: ordinary next-token cross entropy;
- NextLat: `lambda_mse = lambda_kl = lambda_ce = 0` during adaptation, so only the
  same next-token CE acts on both models;
- effective batch 512, block size 1,024;
- fixed episode order; no early stopping or checkpoint selection;
- final update exposure: 52,428,800 tokens per branch.

An episode is not replaced if it fails. Exact checkpoint resume is allowed; changing
the stream, number of updates, or seed is not.

## Measurements and estimands

All hidden states are the final post-normalization state at the last token of the
512-token prefix. For each model, seed, and episode:

1. At the immutable parent checkpoint, L2-normalize the 2,000 retention states and
   4,096 episode-anchor states.
2. For retention document `i`, define proximity `P_i` as the negative median cosine
   distance to its 16 nearest episode anchors. The sign makes larger values mean
   closer geometry.
3. Score mean teacher-forced CE on the fixed 128-token continuation before and after
   adaptation. Define forgetting `F_i = CE_post,i - CE_pre,i`; positive values mean
   erosion.
4. The branch-level primary statistic is Spearman `rho(P, F)` across the 2,000
   documents.
5. Fisher-transform branch correlations, average the two episodes within seed, and
   compute the paired model contrast
   `z_rho(NextLat) - z_rho(GPT)`. The directional prediction is positive: proximity
   is expected to be more informative about interference under NextLat's organized
   geometry.

Report every seed and episode, the paired mean contrast, a seed-paired interval, and
a document-cluster bootstrap interval. The bootstrap quantifies document sampling
uncertainty; it does not manufacture additional independent model seeds.

### Required secondary measurements

- raw and relative continuation-CE erosion;
- global retention CE shift and fraction of documents with positive erosion;
- acquisition CE change on a fixed 2,000-sequence episode sample;
- proximity--forgetting association after rank residualization for pre-update CE,
  GPT-2 unigram frequency, prefix length (fixed), and token 1--4-gram Jaccard to the
  nearest update anchor;
- two negative controls fixed before outcomes: a cyclic permutation of anchor sets
  by 1,367 positions and input-embedding-layer proximity;
- frozen linear probes for future-token offsets 1, 5, 10, and 20, trained on the
  base split and evaluated only on retention documents.

The future-token probes reproduce the measurement family used in the paper, but the
observed future token is one sample from an unknown conditional distribution. Probe
decodability is not an oracle predictive-state metric.

## Failure rules and reporting discipline

- NaN/Inf, invalid hashes, corpus leakage, or non-resumable checkpoint corruption
  makes the affected branch failed and reported.
- Mean acquisition must improve (`CE_post < CE_pre`) for a branch to be interpreted
  as a successful learning intervention. A failure is reported; update count is not
  extended.
- Base validation CE is reported for both models. A competence gap remains a
  limitation and is not repaired by outcome-selected checkpoints or subsets.
- No layer, offset, nearest-neighbor count, distance, endpoint, seed, document, or
  episode may be selected after outcomes.
- Primary and secondary results are reported even when null. Secondary analyses
  cannot promote NL-1 into evidence for exact predictive equivalence or causal
  mediation.

## Launch condition

NL-1 is **not launch-ready**. Launch requires all of the following, completed without
opening scientific outcomes:

1. the document-aware partitioner and split validator;
2. immutable corpus/tokenizer/shard receipts;
3. a 200-update GPT and 200-update NextLat profile using discardable weights, with
   timing, peak memory, and checkpoint overhead only;
4. a cost projection from the measured seconds/update;
5. explicit approval of that projected budget.

The outcome-independent compute decision is binary. Launch the complete frozen
2B-token, three-seed-pair design only if the profile projects **no more than 120
wall-hours and no more than USD 35 in incremental GPU rental**, and the user then
explicitly approves that measured projection. If either ceiling is exceeded, NL-1
is recorded `NO_LAUNCH_COMPUTE_CAP`; there is no one-seed, shorter-token, narrower,
or shorter-context scientific fallback under the NL-1 identifier.

The profile cannot be treated as a model seed, and its losses or representations
cannot enter the scientific report.

This launch gate is independent of TS-1's separately frozen timing/cost gate. A
feasible or successful TS-1 does not authorize NL-1, and an infeasible NL-1 does not
permit a smaller, outcome-selected substitute. If either arm is not executed, the
report must say that the two-layer language program is incomplete and omit the full
language external-validity claim.
