# TS-1: TinyStories parity and language positive control

**Protocol date:** 2026-08-24  
**Study status:** prospectively declared; **not launch-ready**  
**Scientific role:** first layer of the required natural-language program  
**Outcome status at declaration:** no TS-1 corpus, model, probe, or metric was
downloaded, trained, or inspected

## Purpose and claim boundary

TS-1 asks whether this project can reproduce the central representational pattern
reported by NextLat v4 on the authors' own language task:

> After matched TinyStories pretraining, do frozen NextLat hidden states support
> lower held-out future-token probe cross-entropy than frozen GPT hidden states at
> long token offsets without sacrificing offset-1 decodability?

This is a **focused parity/positive-control arm**, not a new forgetting experiment.
It bridges the controlled tasks to the exact future-token-probe measurement family
used in v4. It also checks that the pinned training and probe stack can recover an
already-reported qualitative effect before FineWeb-Edu is used for the new
geometry--forgetting question.

TinyStories does not solve the natural-data concern by itself. Its stories were
generated by GPT-3.5 and GPT-4, and a future token is an observed sample rather than
an exact predictive-state label. TS-1 therefore supports a claim about linear
future-token decodability in synthetic English, not exact belief-state recovery,
human-authored language, causal mediation, or forgetting.

TS-1 cannot rescue a null or failure in HMM, CFS-2, Path-Star, or FineWeb-Edu. If it
passes while a core study is null, it establishes only implementation fidelity and
the limited synthetic-language parity result. If it fails, the discrepancy must be
reported and resolved as a parity failure; no TS-1 setting may be tuned using the
failed scientific metrics.

## Frozen upstream target

The implementation target is NextLat commit
`3770be6009cea2b3c455a9ce7f2ca88b504bb955` and the repository's TinyStories
artifacts. The dataset is `cyrilzhang/TinyStories2-ascii`, pinned prospectively to
Hugging Face repository revision
`eec46cef1415d7fb803f866bf5cc77da39e961fc`. That revision was obtained from remote
repository metadata only; no examples or outcomes were downloaded when this
protocol was written.

The authors report 2.7 million synthetic stories, a 1,000-token vocabulary,
256-token packed sequences, 100,000 base-training steps (about 8.5 epochs), and
20 independent linear probes trained for a further 20,000 steps on the frozen
hidden states. TS-1 preserves those quantities.

The focused comparison contains:

- GPT with ordinary next-token training;
- NextLat with horizon `d=1`, Smooth-L1 weight `1.0`, KL weight `1.0`, and
  projection factor `1.3`, materializing the pinned configuration's official sweep
  values;
- paired seeds `1234`, `1235`, and `1236`. Seed 1234 is the upstream default; the
  other two are fixed robustness repetitions chosen before outcomes.

The paper also reports NextLat `d=8`, BST, MTP, and JTP. They are not included in
this focused arm because the project's forgetting hypotheses concern GPT versus
one-step NextLat, not ranking all v4 objectives. TS-1 must consequently be described
as a **focused GPT/NextLat-d=1 parity check**, never as a full reproduction of the
paper's TinyStories comparison.

## Base training

For every model and seed:

- 8 layers, 8 heads, hidden width 768, no bias or dropout;
- vocabulary 1,000 and block size 256 using the pinned tokenizer;
- effective batch 256;
- 100,000 optimizer updates, hence
  `100000 * 256 * 256 = 6,553,600,000` packed-token exposures per run;
- AdamW, learning rate `3e-4`, weight decay `0.1`, betas `(0.9, 0.95)`, gradient
  clip `1.0`, and the pinned constant schedule with no warmup or warmdown;
- final update-100,000 weights only for scientific probing. Intermediate
  validation is logged for audit, but neither the best-validation checkpoint nor
  an early-stopped checkpoint may be selected.

Base training produces six scientific runs and 39,321,600,000 total packed-token
exposures. Physical microbatch and gradient accumulation may change only to preserve
the effective batch exactly on a single GPU. Precision, compilation, packing,
document-boundary masking, tokenizer, and random seeds must be written to a
pre-launch execution receipt.

The pinned data module calls the Hugging Face dataset without a revision and does
not retain the value returned by `Dataset.shuffle`. The launch implementation must
therefore inject the frozen revision without changing examples and record an exact
ordered-example/packed-sequence receipt for each seed. This is a reproducibility
repair, not permission to filter, resample, or inspect text based on model behavior.

## Frozen probes and estimands

After each final base checkpoint, freeze every transformer parameter. Use the
pinned one-layer probe implementation and the paired GPT/NextLat probe configs:

- offsets 1 through 20, where logged index 0 is offset 1;
- all 20 independent linear token heads trained jointly by the repository harness;
- 20,000 optimizer updates on the same pinned TinyStories training split;
- effective batch 256, block size 256, AdamW `3e-4`, weight decay `0.1`, betas
  `(0.9, 0.95)`, and gradient clip `1.0`;
- evaluation on the pinned validation split;
- final update-20,000 probe only, with no checkpoint or offset selection.

The probe module also fits a nonlinear next-hidden-state decoder and includes its
MSE in the joint loss. That behavior is present in the pinned code and is retained
for parity. Claims concern only the 20 linear token-head cross-entropies; the decoder
MSE is diagnostic and cannot select a probe checkpoint.

For seed `s` and token offset `k`, define

```text
Delta[s,k] = CE_probe_GPT[s,k] - CE_probe_NextLat_d1[s,k]
```

so positive values favor NextLat. The primary seed-level estimand is

```text
LongHorizonDelta[s] = mean(Delta[s,k] for k = 10,...,20).
```

Report all 20 offset contrasts for every seed, the paired seed mean and interval for
`LongHorizonDelta`, and raw cross-entropies. The preregistered positive-control
criterion is:

1. mean `LongHorizonDelta` across the three seeds is positive; and
2. at least 8 of the 11 offsets from 10 through 20 have positive seed-mean
   `Delta`; and
3. at offset 1, the absolute seed-mean contrast is no more than `0.02` nats.

The third threshold operationalizes the paper's “matches GPT” claim. It is a parity
criterion, not an equivalence test with adequate power. Results remain reportable
if any criterion fails; no seed, offset, or checkpoint may be removed.

## Outcome-blind execution and stopping

Before scientific training, timing/memory profiles may run 200 discardable updates
for each base architecture and 200 discardable probe updates on randomly initialized
frozen backbones. Profiles may record only seconds/update, GPU memory, effective and
physical batch, compilation/precision, and checkpoint overhead. Losses, probe CE,
generations, and hidden states may not be opened. Profile weights may not enter
TS-1.

Choose the largest fitting physical microbatch from
`[256, 128, 64, 32, 16, 8, 4, 2, 1]`, with integer accumulation preserving effective
batch 256. If microbatch 1 does not fit, record a hardware block rather than changing
width, sequence length, or batch.

The complete six-base/six-probe study may launch only if the immutable profile
projects no more than **180 two-GPU wall-hours** and **USD 55 incremental GPU
rental**, and the user explicitly approves that projection. If either ceiling is
exceeded, record `NO_LAUNCH_COMPUTE_CAP`. There is no smaller scientific TS-1
fallback. A smoke test may run with outputs unopened, but cannot become evidence.

Exact checkpoint/RNG resume after interruption is allowed. Replacing a seed,
selecting a checkpoint, reducing steps, changing the dataset revision, or opening a
profile metric beyond timing/memory creates a new study rather than TS-1.

## Required reporting

The report must call TinyStories synthetic language, identify the focused d=1-only
scope, show all offsets and seeds, and state whether all three parity criteria
passed. It must not claim that TS-1 measures forgetting or natural-web-text external
validity. Full language-program claims require both TS-1 and the separately declared
FineWeb-Edu NL-1 arm.
